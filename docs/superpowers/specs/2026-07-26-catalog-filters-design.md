# Фильтры каталога по типу, городу, району, комнатам и цене

## Цель

Обновить фильтры каталога так, чтобы пользователь мог последовательно выбрать тип объекта, город, район, число комнат и диапазон цены. Значения города и района должны отражать опубликованные объекты, синхронизированные из Topnlab.

## Интерфейс

Фильтры отображаются в следующем порядке:

1. «Тип объекта» — варианты «Квартира», «Дом», «Земельный участок» и нейтральное значение «Любой».
2. «Город» — список городов из объектов с `isFeed: true`.
3. «Район» — список районов только выбранного города.
4. «Комнаты» — варианты «Любое», 1, 2, 3, «4 и больше».
5. «Цена от» — необязательная нижняя граница в рублях.
6. «Цена до» — необязательная верхняя граница в рублях.

Кнопки «Показать» и «Сбросить» сохраняются. Если город не выбран, фильтр района недоступен и предлагает сначала выбрать город. Выбор города отправляет GET-форму, после чего страница возвращается с сохранёнными значениями остальных полей и актуальным списком районов этого города. Отдельный клиентский API и запрос к Topnlab из браузера не требуются.

## Данные и синхронизация

В модель `Property` добавляется необязательное поле `city`. Оно заполняется из полей города сущности Topnlab при общей синхронизации и обновлении контента. Значение очищается от служебных пробелов и приводится к единому отображаемому виду, аналогично нормализации адреса.

Существующие объекты получают город при следующей штатной синхронизации Topnlab. До этого объекты без `city` продолжают отображаться в каталоге, но не входят в список городов и не находятся по городскому фильтру.

Типы интерфейса сопоставляются с хранимым `objectType`:

- «Квартира» — `flat`;
- «Дом» — `house`;
- «Земельный участок» — `land`.

Другие типы объектов не исчезают из каталога при нейтральном фильтре, но не добавляются как отдельные варианты.

## Фильтрация

GET-параметры каталога: `objectType`, `city`, `district`, `rooms`, `priceMin`, `priceMax`.

- Все выбранные условия применяются совместно.
- Нижняя и верхняя границы цены включительны (`gte` и `lte`).
- Если заполнена только одна граница, применяется только она.
- Некорректные, отрицательные или нечисловые значения цены игнорируются.
- Если минимальная цена больше максимальной, обе корректные границы всё равно формируют пустой результат без автоматической перестановки значений.
- Район применяется только вместе с выбранным городом, чтобы одинаковые названия районов разных городов не смешивались.
- Значение комнат `4` означает четыре комнаты и больше.

## Получение списков

Список городов строится из уникальных непустых значений `city` опубликованных объектов и сортируется по русскому алфавиту. Список районов строится из уникальных нормализованных районов опубликованных объектов выбранного города и также сортируется по русскому алфавиту.

## Проверка

Автоматические тесты должны подтвердить:

- извлечение и нормализацию города из ответа Topnlab;
- сохранение города в отображаемой модели объекта;
- корректное построение условий по типу, городу, району, комнатам и обеим границам цены;
- игнорирование некорректных ценовых параметров;
- наличие полей в нужном порядке и утверждённых вариантов типа объекта;
- недоступность района без города и выбор районов только для указанного города.

Перед завершением выполняются целевые тесты, полный набор тестов и production build. Существующие lint-ошибки, перечисленные в `PROJECT_CONTEXT.md`, не входят в область этой задачи; новые или изменённые файлы не должны добавлять ошибок.

## Вне области задачи

- загрузка данных Topnlab напрямую при открытии страницы;
- новые типы объектов сверх трёх утверждённых вариантов;
- изменение карточек объектов;
- публикация на сервер без отдельного запроса пользователя.
