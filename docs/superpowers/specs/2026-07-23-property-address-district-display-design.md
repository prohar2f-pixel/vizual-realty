# Адреса, районы и описание объектов

## Цель

Во всех карточках объектов показывать полный читаемый адрес, компактное описание и настоящий район объекта. Фильтр каталога должен содержать районы, а не города.

## Причина ошибки

Topnlab передаёт город и район разными полями. Текущий импорт записывает в `Property.district` общее поле `district`, которое в реальных данных содержит город (`Донецк г.`). Настоящий район приходит в `city_district` или `city_district_name`. Каталог строит фильтр из сохранённого `Property.district`, поэтому показывает города.

## Нормализация района

Добавляется единая функция извлечения района из объекта Topnlab:

1. Сначала используется `city_district_name`.
2. Затем `city_district`.
3. Затем `district_name` или `district`, только если значение не совпадает с городом.
4. Вложенные значения вида `{ name: "Пролетарский р-н" }` поддерживаются.
5. Пустое значение возвращается как `undefined`; выдумывать район по улице нельзя.

Нормализованный район записывается в `Property.district`. Все страницы и фильтр продолжают читать это поле, поэтому единое исправление применяется ко всему каталогу.

## Формат адреса

Адрес собирается из структурированных полей Topnlab в порядке:

`регион, город, район, улица, дом`

Пример:

`Донецкая Народная Республика, г. Донецк, Пролетарский р-н, ул. Раздольная, д. 26`

Правила:

- уже присутствующие сокращения не дублируются;
- для известных полей без префикса добавляются `г.`, `р-н`, `ул.` и `д.`;
- одинаковые части удаляются без учёта регистра;
- если структурированных данных недостаточно, используется готовый полный адрес Topnlab;
- существующий короткий адрес используется только как последний резерв.

## Описание

HTML-разрывы строк по-прежнему преобразуются в безопасный текст. На странице объекта описание разбивается по пустым строкам на отдельные абзацы. Одиночные переносы внутри одного смыслового блока сохраняются. Между абзацами используется компактный одинаковый интервал, без больших пустых зон.

## Синхронизация существующих объектов

Текущая безопасная синхронизация контента расширяется полем `district`. Она обновляет только:

- `address`;
- `description`;
- `district`.

Она не изменяет цену, фотографии, тип объекта, статус публикации или закреплённого менеджера. Объекты, отсутствующие в локальной базе, пропускаются.

## Фильтр каталога

Фильтр продолжает строиться из уникальных непустых значений `Property.district`. После синхронизации это будут реальные районы. Значения сортируются по русскому алфавиту; дубли исключаются базой.

## Проверки

Автоматические тесты должны подтвердить:

- извлечение `Пролетарский р-н` из `city_district`;
- приоритет `city_district` над городом в `district`;
- защиту от использования города в качестве района;
- поддержку вложенных значений `{ name }`;
- полный адрес с понятными префиксами;
- безопасное обновление только трёх контентных полей;
- корректное отображение описания без буквальных HTML-тегов.

После тестов выполняются TypeScript-проверка и production-сборка. Локальный результат показывается пользователю до публикации.
