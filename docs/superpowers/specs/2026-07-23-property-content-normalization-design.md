# Нормализация карточек объектов

## Цель

Карточка каждого объекта на сайте должна аккуратно повторять данные Topnlab:

- аватар ответственного менеджера имеет фирменную зелёную рамку;
- адрес отображается одной понятной строкой от региона до номера дома;
- описание сохраняет абзацы и переносы строк, но не показывает пользователю HTML-теги;
- старые или неполные записи продолжают отображаться без ошибок.

Форма заявки в эту работу не входит. Она остаётся без изменений до решения заказчика о маршруте обращения.

## Причины проблем

1. Компонент `AgentCard` обрезает фото по кругу, но не задаёт рамку.
2. Описание хранится с HTML-переносами `<br>`, `<br/>` или `<br />`, а React выводит строку как обычный текст.
3. Текущий импорт сохраняет только сокращённое поле `address`. Составные поля Topnlab, из которых CRM формирует полный адрес, не используются.
4. Полагаться только на исправление разметки нельзя: интерфейс не может восстановить район или регион, которых нет в локальной записи.

## Выбранное решение

### Внешний вид менеджера

Круглый аватар получает зелёную рамку толщиной 3 px и тонкий белый внутренний отступ. Размер карточки и фотографии не меняется.

### Описание

Отдельная чистая функция нормализует текст:

1. переводит все варианты `<br>` в перенос строки;
2. переводит закрывающие блочные теги в перенос строки;
3. удаляет остальные HTML-теги;
4. декодирует основные HTML-сущности;
5. убирает пробелы в концах строк и лишние пустые строки.

Результат выводится как обычный текст, без `dangerouslySetInnerHTML`. Это сохраняет форматирование и исключает выполнение HTML из CRM.

### Адрес

Импорт формирует полный адрес из доступных компонентов Topnlab в естественном порядке:

1. регион;
2. город или населённый пункт;
3. внутригородской район;
4. улица;
5. дом.

Повторяющиеся части удаляются. Если составных полей недостаточно, используется готовое поле полного адреса Topnlab, затем существующее сокращённое поле `address`. Текущие записи обновляются одной синхронизацией активных объектов.

### Устойчивость импорта

Маппер принимает варианты названий полей, реально встречающиеся в ответах Topnlab, и не прекращает всю синхронизацию из-за одной неполной карточки. Обязательные поля получают проверяемые резервные значения только там, где это безопасно; некорректная карточка пропускается с понятным сообщением.

## Проверка

Автоматические тесты покрывают:

- все варианты HTML-переносов и лишних тегов;
- несколько абзацев и пустых строк;
- полный адрес из компонентов;
- удаление повторов в адресе;
- резервный сокращённый адрес;
- объект с неполными полями;
- зелёную рамку аватара на уровне компонента или его классов.

После тестов выполняются сборка и локальная визуальная проверка минимум трёх объектов с разными адресами. На рабочий сайт изменения попадают только после локального просмотра заказчиком.

## Откат

Код откатывается предыдущим Git-коммитом. Обновлённые адреса и описания можно повторно получить из Topnlab после возврата старого маппера; структура базы данных не меняется.
